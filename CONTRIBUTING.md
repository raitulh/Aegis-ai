# Contributing

Thanks for helping improve Aegis. Start with [AGENTS.md](AGENTS.md) — it is the source of truth for conventions.

## Non-negotiables

1. **Engines are pure.** Code under `engines/` must not import the database, FastAPI or app services.
2. **Tenant data goes through `get_db`** (the RLS-scoped session). Only identity/onboarding, migrations and seeding use the admin session.
3. **Evidence is immutable.** Never update or delete `evidence` rows or edit a hash chain.
4. **No built-in attacks.** The red-team engine runs an imported corpus only.
5. **No compliance claims.** Use "assessment", "readiness", "aligned to" — never "certified", "compliant" or "guaranteed".
6. **No fabricated numbers.** Every number shown in the product comes from real data; demo data is generated by the real engines and marked DEMO.

## Workflow

```bash
uv sync && pnpm install
pnpm lint && pnpm typecheck && pnpm test && pnpm build
pnpm --filter @aegis/web test:e2e        # needs PostgreSQL (see docs/testing.md)
```

- Changes to the API surface or engine behaviour need tests under `tests/` (unit for engines, integration for API/RLS, evaluation for engine correctness).
- Migrations must include a working `downgrade()`; CI runs `alembic check` and a downgrade/upgrade round-trip.
- Keep commits small and focused with imperative subjects.

## Reporting security issues

Do not open a public issue. Use the contact form's "security review" option or contact the maintainers privately with reproduction steps.

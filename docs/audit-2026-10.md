# Repository audit — October 2026

This document records the Stage 1 audit of the Aegis codebase that preceded the production-hardening
work, the prioritized remediation list, and what was done about each item. It is intentionally blunt:
items are listed with the evidence that led to them, and their status reflects what was verified, not
what was intended.

Priority scale: **P0** security / data loss / correctness / production blocker · **P1** reliability /
scalability / enterprise-critical · **P2** UX / performance / developer experience · **P3** nice-to-have.

## Architecture map (as found)

```
Browser ──▶ Next.js 16 (apps/web) ──▶ BFF route handler /bff/[...path] ──▶ FastAPI /api/v1
                                                                            │
         get_current_principal (admin session, identity tables, no RLS) ◀──┤
         get_db (app role, RLS via set_config('app.current_org_id'))    ◀──┤
                                                                            │
         services/*  ──▶ engines/* (pure evaluators)                        │
         after_commit hooks ──▶ jobs.dispatcher ──▶ Celery (Redis) | thread pool
                                   │
                                   └─▶ orchestrator.run_audit ──▶ test_results, evidence (hash chain),
                                         findings, reports, risk snapshots, audit_events
SSE /audits/{id}/stream polls audit_events every 500 ms.
```

Traced flows: signup → org provisioning → system creation → audit creation (after-commit dispatch) →
orchestrator stages → evidence chain → findings (fingerprint dedup) → report → SSE → UI; agent trace
ingestion → deterministic tool-call policy checks → `tool_calls` rows (no findings, no runtime decision).

## Findings

### P0

| # | Area | Finding | Evidence | Status |
| --- | --- | --- | --- | --- |
| P0-1 | Jobs / audits | Whole audit ran in one DB transaction: progress events were invisible to the SSE stream until the audit finished ("live" progress was not live). | `orchestrator.AuditRunner.emit` only `flush()`es; the job session commits once at the end. | Fixed — progress is written through a separate, immediately-committed channel. |
| P0-2 | Jobs / audits | Cancel blocked on a row lock for the full audit duration, then the runner overwrote `cancelled` with `completed` (lost update). | Runner updates `audits` early in its long transaction; `cancel_audit` updates the same row; `_finalize` never re-checks. | Fixed — cancellation is cooperative and the terminal write is a conditional update. |
| P0-3 | Jobs / audits | Duplicate deliveries (Celery `acks_late` redelivery, double dispatch) ran the same audit twice, producing duplicate results, evidence and findings. | `run_audit` checks status with a plain read; nothing claims the audit. | Fixed — atomic `queued → running` claim with a lease; second delivery is a no-op. |
| P0-4 | Findings | Finding numbers were allocated by read-modify-write on `organizations.finding_seq`; two concurrent audits in one workspace collided on `uq_findings_org_number` and the second audit failed. | `finding_service._next_number`, `redteam_service._num`. | Fixed — atomic `UPDATE … RETURNING` allocation in its own short transaction. |
| P0-5 | Findings | A re-observed finding had its `audit_id` overwritten, so it "moved" to the newest audit. Audit comparison and per-audit finding lists were wrong (findings vanished from the earlier audit). | `finding_service.create_from_group` (`existing.audit_id = audit.id`); `audit_service.compare_audits` keyed on `Finding.audit_id`. | Fixed — new `finding_occurrences` table records every (finding, audit) observation; comparison uses it. |
| P0-6 | Findings | Deduplication fingerprint was matched across the whole organization, not per system, so the same issue on two systems merged into one finding. | `Finding.fingerprint` lookup filtered only by org. | Fixed — dedup is scoped to `(organization, system, fingerprint)`. |
| P0-7 | SSRF | URL validation resolved DNS once, then `httpx` resolved again at connect time (DNS-rebinding TOCTOU). `is_private` also missed CGNAT (`100.64.0.0/10`), NAT64 and 6to4 ranges. | `security/ssrf.py`, `providers/http_endpoint.py`, `webhook_service`. | Fixed — connect-time validating transport pins the vetted IP; `is_global` semantics. |
| P0-8 | SSRF | Provider base URLs always allowed private networks, so any workspace admin in a multi-tenant deployment could reach internal services. | `system_service.create_provider` (`allow_private=True`). | Fixed — governed by `ALLOW_PRIVATE_NETWORK_TARGETS`. |
| P0-9 | RBAC | An admin could change the workspace owner's role (e.g. demote the owner to viewer). | `workspace.change_role` checks only the *target* role. | Fixed — owner memberships can only be changed by an owner; the last owner cannot be demoted. |
| P0-10 | Integrity | Evidence / audit-log immutability triggers could be bypassed by the RLS-bound app role setting the custom GUC `aegis.allow_evidence_delete`. | Migration 0002 trigger functions. | Fixed — the purge path additionally requires a role that is not a member of `aegis_app` (or superuser). |
| P0-11 | Availability | Each SSE stream held an admin-pool DB connection for its lifetime (FastAPI ≥ 0.118 closes `yield` dependencies after streaming). ~8 open audit pages exhausted the admin pool and blocked authentication for everyone. | `deps._raw_session` used by `get_current_principal`. | Fixed — identity resolution uses a short-lived session. |
| P0-12 | Rate limiting | `X-Forwarded-For` was trusted unconditionally, so the public/login rate limit was bypassable by rotating the header. | `ratelimit.client_ip`. | Fixed — only trusted when `TRUSTED_PROXY_HOPS` > 0. |
| P0-13 | Auth | No per-account login throttling (credential stuffing across IPs). | `auth_service.login`. | Fixed — per-email failure limiter. |

### P1

| # | Area | Finding | Status |
| --- | --- | --- | --- |
| P1-1 | Jobs | No periodic scheduler: webhook deliveries were enqueued but never sent; expired guest sandboxes were never purged; no stale-run recovery. | Fixed — `maintenance` jobs run by Celery beat or the inline scheduler. |
| P1-2 | Jobs | No retry/backoff/failure classification; no job ledger. | Fixed — `job_runs` ledger with idempotency keys and classified failures. |
| P1-3 | SSE | No `Last-Event-ID` resume (reconnect replayed everything), no heartbeat, no permission check (`audits:read`). | Fixed. |
| P1-4 | API | Non-idempotent POSTs retried by the SDK could create duplicate audits. | Fixed — `Idempotency-Key` support (API + SDK). |
| P1-5 | CSRF | Cookie-authenticated unsafe requests had no Origin check (SameSite=Lax is the only control). | Fixed — Origin/Referer guard for cookie-authenticated unsafe methods. |
| P1-6 | Health | `/ready` returned 200 when the database was down. | Fixed — 503 when not ready; `/live` added. |
| P1-7 | Evidence | A verification function existed but no endpoint, export, or signature. | Fixed — verification endpoint, signed export bundle, standalone verifier. |
| P1-8 | Team | Invitations were created but could never be accepted. | Fixed — accept endpoint. |
| P1-9 | Webhooks | No API to create, list, test or delete webhooks. | Fixed. |
| P1-10 | Runtime | Agent traces were recorded but no runtime decision (allow/flag/block/approve) existed. | Added — Runtime Guard. |
| P1-11 | Config | Production accepted wildcard CORS and dev secrets were only checked for two keys. | Fixed — stricter production validation. |
| P1-12 | Data | `change_impact` reported `affected_tests = controls × 5` — an invented number. | Fixed — counts real regression tests and automated controls. |

### P2 / P3

* README documented an SDK API that does not exist (`AegisClient`, `client.traces.create(prompt=…)`). Fixed.
* README claimed "court-admissible" evidence. Removed (defensible terms only).
* `orchestrator._fact_questions` contained dead code; `row.setdefault_evidence` junk attribute. Cleaned.
* README images showed fabricated telemetry (a nonexistent CLI and an invented score). Removed.
